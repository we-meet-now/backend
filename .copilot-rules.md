# Wemeetnow Backend API Response Convention

This document defines the strict API response convention for the `auth_service` backend. GitHub Copilot must follow these rules for all controller and DTO creations or modifications.

## 1. Universal Response Format
Every Controller method must return `ResponseEntity<CommonApiResponse<T>>`.
- **NEVER** return raw DTOs, `String`, or `Void` directly inside `ResponseEntity`.
- Always wrap the response payload using `CommonApiResponse.<T>builder()`.

### Example Structure:
```json
{
  "statusCode": "2000",
  "data": { ... },
  "message": "성공 메시지"
}
```
## 2. Business Status Code (statusCode) Rules
-Success (2xx): Use "2000", "2010" (Created), "2020" (Accepted), etc.

-Client Error (4xx): Use "4000" (Bad Request), "4010" (Unauthorized/Expired), "4040" (Not Found).

-Server Error (500): Use "5000".

## 3. Error & Exception Handling in Controllers
When returning an error status (e.g., 401, 404), you MUST still wrap it in CommonApiResponse with data(null).

- Bad: ResponseEntity.status(HttpStatus.NOT_FOUND).build()

- Good:

```Java
return ResponseEntity.status(HttpStatus.NOT_FOUND).body(
    CommonApiResponse.<TargetDto>builder()
        .statusCode("4040")
        .data(null)
        .message("에러 메시지")
        .build()
        );
```
## 4. Swagger (Springdoc OpenAPI) Rules
- @ApiResponse의 content 속성에는 실제 반환 타입인 CommonApiResponse.class를 지정해야 합니다.
- @Content(schema = @Schema(implementation = CommonApiResponse.class))
